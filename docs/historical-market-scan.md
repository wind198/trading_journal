# Historical scan

Automatically scan latest completed data on workspace mount. No polling or automatic trade evaluation. History accepts browser-local datetime (15-minute granularity, rounded down in UTC), or Pick M15 then tap an actual candle in the M15 pane. Historical point means candle CLOSE, not open. Server validates canonical UTC ISO, positive aligned cutoff, no future block, auth and fixed 400 candles per timeframe. Existing exclusive bucket-open query and completedBars filter enforce one cutoff for both timeframes. Historical Refresh repeats the same cutoff; Latest returns to current scan. Successful snapshot change resets entry/SL/TP/options, retains direction. Failed/cancelled request preserves previous snapshot, and aborted responses cannot replace it. React Strict Mode may start then abort an extra development request. No fabricated candles or forward-replay data; gaps remain data quality warnings. Date picker can request older available rollups beyond currently plotted history. Historical scan is reconstructed from stored rollups, not a point-in-time database version audit. Tests added but not executed; build/browser not verified, installed Next/chart docs unavailable. No migrations/dependencies.
